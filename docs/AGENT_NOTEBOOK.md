# Agent Notebook：分析记录、追问与球探报告

## 目标

`v0.9.0` 把一次性的双球员分析升级为可恢复的分析工作流：

```text
新建分析 → 保存结构化快照 → 最近记录 → 恢复 → 继承范围追问 → 打印球探报告
```

该功能不改变指标计算口径。千问仍只负责组织已经计算出的证据；未配置或调用失败时继续使用本地规则引擎。

## 数据模型

Alembic 迁移 `20260808_0003` 新增 `agent_runs` 表。主要字段：

| 字段 | 含义 |
|---|---|
| `run_id` | 对外使用的分析记录 ID |
| `parent_run_id` | 追问所继承的父记录；独立分析为空 |
| `follow_up_depth` | 从独立分析开始计算的追问层级 |
| `question` | 本次任务描述 |
| `season` | 本次分析使用的赛季口径 |
| `requested_focus` / `resolved_focus` | 用户请求与最终识别的分析重点 |
| `player_a_slug` / `player_b_slug` | 锁定的双球员范围 |
| `winner_slug` | 本地计算确定的推荐球员 |
| `generation_mode` | `local_rules` 或 `qwen_enhanced` |
| `result_snapshot` | 完整结构化结果的 JSON 快照 |
| `created_at` | 记录创建时间 |

保存完整快照可保证历史报告不会因为后续模板变化而静默改写。

## API

| 方法 | 路径 | 作用 |
|---|---|---|
| `POST` | `/api/agent/analyze` | 执行分析并自动保存记录 |
| `GET` | `/api/agent/runs?limit=8&offset=0` | 获取最近分析摘要 |
| `GET` | `/api/agent/runs/{run_id}` | 恢复完整分析与报告来源信息 |
| `POST` | `/api/agent/runs/{run_id}/follow-up` | 继承父记录范围并创建一条新分析 |

追问请求只接收：

```json
{
  "question": "如果更重视创造机会，结论会改变吗？",
  "focus": "creativity"
}
```

后端从父记录继承球员和赛季，不允许前端在追问过程中悄悄替换分析对象。随后重新查询数据库、换算每 90 分钟指标、计算百分位与证据权重，并增加 `run_memory` 工具步骤。

## 球探报告

前端路由 `/reports/{run_id}` 展示：

- 分析任务、记录 ID、生成时间与生成模式；
- 双球员资料、Agent 得分与置信度；
- 指标值、权重和 450+ 分钟合格球员池百分位；
- 三条关键证据与完整工具执行轨迹；
- 父记录和追问深度；
- 数据来源、比较范围与结论边界。

“打印 / 保存 PDF”使用浏览器标准打印功能，不在服务器生成或保存 PDF。打印样式为 A4，并避免把关键卡片拆到两页。

## 存储与隐私边界

- 当前项目没有账号系统，所有记录属于当前数据库实例，不区分用户。
- SQLite 数据库被 `.gitignore` 忽略，分析记录不会随源码上传 GitHub。
- 项目没有跨设备同步、公开分享、删除或保留期策略。
- 若未来上线多人版本，必须先增加用户归属、访问控制和数据删除接口，再开放记录功能。
