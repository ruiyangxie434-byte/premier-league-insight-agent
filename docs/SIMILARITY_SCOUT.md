# Similarity Scout 算法与边界

## 功能范围

`v0.13.0` 在球员详情页加入可解释的同位置相似球员模块。它回答的是“在这份固定赛季快照和当前指标范围内，哪些记录的统计画像更接近”，而不是“谁和目标球员一样强”或“应该买谁”。

```text
目标球员记录
  → 选择达到分钟门槛的同位置候选
  → 计算七项同位置百分位
  → 按位置权重汇总画像距离
  → 返回相似分、接近指标与最大差异
```

页面支持 `450`、`1800` 和 `2700` 分钟候选门槛，默认返回最接近的 5 条记录。

## 候选池规则

1. 数据范围固定为 2024-25 英超球员历史快照。
2. 候选记录必须与目标球员位置相同，并达到当前分钟门槛。
3. 目标球员本人以及同名的其他俱乐部分段全部排除，避免转会记录自我推荐。
4. 目标记录本身可以低于候选门槛；它仍会和合格池比较，但页面保留真实分钟数。
5. 没有有效比赛分钟的记录不生成相似度。

## 指标与位置权重

输入使用后端统一计算的七项每90指标。每个指标先转换为同位置合格池百分位，再按下表加权：

| 指标 | 前锋 | 中场 | 后卫 |
|---|---:|---:|---:|
| 进球 / 90 | 25% | 10% | 5% |
| 助攻 / 90 | 15% | 16% | 8% |
| 射门 / 90 | 18% | 10% | 5% |
| 关键传球 / 90 | 16% | 22% | 12% |
| 抢断 / 90 | 8% | 16% | 25% |
| 拦截 / 90 | 6% | 14% | 30% |
| xG / 90 | 12% | 12% | 5% |

每个位置的权重合计为 100%，并由 API 原样返回，因此页面展示与后端计算使用同一口径。

## 相似分

对指标 `m`，记目标球员百分位为 `P_target,m`，候选球员百分位为 `P_candidate,m`，位置权重为 `w_m`：

```text
加权距离 = Σ w_m × |P_target,m - P_candidate,m|
相似分   = round(100 - 加权距离)
```

结果限制在 `0–100`。100 只表示七项输入百分位在当前候选池中完全一致，不代表两名球员现实角色、身体条件、合同价值或未来表现相同。

返回结果同时包含：

- 百分位差距最小的两项“最接近指标”；
- 加权差距最大的“最大画像差异”；
- 实际同位置候选数量与分钟门槛；
- 完整位置权重和方法说明。

同分时按未四舍五入的加权距离、出场分钟、姓名和 slug 稳定排序，保证相同快照得到可复现结果。

## 门将边界

当前快照没有扑救、扑救率、失球、阻止进球或零封字段。使用进球、射门、抢断等外场指标比较门将会让大量零值产生虚假高相似，因此门将详情页明确返回 `is_supported = false` 和原因说明，不生成排行榜。

在补齐可追溯且许可清晰的门将专属字段前，不使用外场权重替代。

## API

```text
GET /api/players/{slug}/similar
```

查询参数：

| 参数 | 默认值 | 范围 |
|---|---:|---|
| `season` | `2024-25` | `YYYY-YY` 格式，当前只有固定赛季有数据 |
| `minimum_minutes` | `450` | `450–4000` |
| `limit` | `5` | `1–10` |

示例：

```text
GET /api/players/bukayo-saka/similar?minimum_minutes=1800&limit=5
```

响应中的候选球员沿用 Player Lab 的累计数据、每90指标和百分位结构，前端不重复计算相似分。

## League Copilot 接入

`v0.13.0` 同时把相似检索注册为第五个受控工具：

```text
find_similar_players(player, season, minimum_minutes, limit)
```

本地路由和千问规划器都只能从 450+ 分钟的唯一球员实体中选择目标，并把参数规范化为 slug。工具复用本页同一后端服务，返回候选证据、来源、方法边界和进入详情页 / 双人雷达的链接；模型不重新计算或修改相似分。

## 已知限制

- 只包含七项可追溯统计，没有传球方向、推进、触球区域、速度、身体对抗或战术角色。
- 百分位会随分钟门槛改变，不同门槛的相似分不能直接横向比较。
- 俱乐部战术、联赛环境和队友质量没有被模型控制。
- 结果是描述性检索，不是机器学习预测、转会估值或因果结论。
