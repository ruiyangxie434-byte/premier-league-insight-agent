# Transfer Signal：可解释的历史统计候选信号

`v0.17.0` 新增 `/transfer` 页面与
`GET /api/clubs/{slug}/transfer-signals` 接口。它从现有 2024-25
球员—俱乐部快照中计算球队位置基线和外队候选信号，不接入实时新闻、身价或合同数据。

## 输入

- `slug`：目标球队 slug；
- `season`：当前固定为 `2024-25`；
- `position`：`GK`、`DEF`、`MID` 或 `FWD`；
- `minimum_minutes`：`450`–`3000`，页面提供 450 / 900 / 1800；
- `limit`：返回 1–12 条候选，页面默认 6 条。

## 计算流程

1. 只保留达到分钟门槛的同位置球员—球队记录；
2. 将进球、助攻、射门、关键传球、抢断、拦截和预期进球转换为同位置每90百分位；
3. 对目标球队同位置记录取平均百分位，形成球队位置基线；
4. 使用 Similarity Scout 的位置权重，结合 `100 - 球队基线百分位` 选出三项优先观察指标；
5. 排除目标球队记录，以及目标球队中已经出现过的同名球员；
6. 只保留在至少一项优先指标上高于球队基线的外队记录；
7. 对同名多段记录保留信号最高的一段，再返回候选列表。

## 信号分

候选信号分为 0–100 的排序值：

```text
signal = 60% × 优先缺口正向提升
       + 30% × 位置加权画像
       + 10% × 分钟样本置信度
```

- 正向提升只计算候选高于球队基线的部分；
- 位置加权画像复用前锋、中场和后卫的七项权重；
- 分钟置信度在 2700 分钟达到 100；
- 页面同时返回最多三项 `key_lifts` 和两项 `tradeoffs`，避免只展示单一总分。

信号分不是能力总评、成交概率、预测或转会建议。

## 门将边界

当前快照缺少扑救、失球、阻止进球、传中处理和出击等门将专属字段。
当 `position=GK` 时，接口会返回 `is_supported=false` 与明确原因，不生成门将排名。

## 未纳入变量

- 身价、转会费、工资和合同年限；
- 伤病、停赛、当前名单与实时可用性；
- 战术职责、惯用脚、阵型适配和更衣室因素；
- 未来表现、谈判意愿和成交概率。

因此该模块适合展示数据建模、可解释排序与决策边界，不应替代真实球探和转会决策。
