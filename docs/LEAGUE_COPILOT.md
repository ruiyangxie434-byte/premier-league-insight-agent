# League Copilot：受控函数调用与证据回答

`v0.11.0` 新增 `/copilot` 工作台，最初注册四个受控工具；`v0.13.0` 加入相似球员检索，`v0.15.0` 加入确定性的球队对阵简报，`v0.16.0` 再加入球队阵容透镜。自然语言模型不能直接读取数据库，也不能绕过工具补充实时事实。

## 目标

此前的双球员 Agent 会按固定顺序执行本地工具，千问只组织最终表述。League Copilot 增加真正的 OpenAI-compatible `tools` / `tool_calls` 流程：

1. 用户提出自然语言问题；
2. 配置千问时，由 `qwen-plus` 从后端提供的工具清单中选择函数与参数；
3. 后端使用 Pydantic 校验工具名称、赛季、实体与参数范围；
4. 后端查询 SQLite 并计算结构化证据；
5. 千问只根据工具返回结果组织 JSON 回答；
6. 页面同时展示答案、证据、调用参数、数据源与限制。

官方接口格式参考 [阿里云百炼 OpenAI 兼容 Function Calling 文档](https://help.aliyun.com/zh/model-studio/compatibility-of-openai-with-dashscope)。

## 工具注册表

| 工具 | 参数 | 数据范围 | 典型问题 |
|---|---|---|---|
| `get_league_table` | `season`、`limit`、可选 `club` | 2024-25 最终 20 队积分榜 | “积分榜前三名是谁？” |
| `get_club_form` | `club`、`season`、`recent_matches` | 2024-25 完整 38 场比分计算 | “利物浦最近五场和主客场怎样？” |
| `analyze_club_squad` | `club`、`season`、分钟门槛 | 2024-25 单队阵容结构快照 | “分析利物浦的阵容结构与队内核心” |
| `compare_clubs` | 两支球队、`season` | 2024-25 八维历史比较与两回合交锋 | “比较利物浦和阿森纳” |
| `compare_players` | 两名球员、`season`、`focus` | 2024-25 的 400 条 450+ 分钟记录 | “萨卡和帕尔默谁更适合创造？” |
| `find_similar_players` | 一名 450+ 分钟球员、`season`、分钟门槛、`limit` | 2024-25 同位置外场球员画像 | “谁和萨卡的统计画像最相似？” |
| `get_match_shot_summary` | `source_match_id` | Match ID `3749448` 的 28 次射门 | “2004 年 4–2 的 xG 如何？” |

模型只能调用上表中的函数。未知工具、未知实体、重复球员、非 `2024-25` 赛季、非法 `focus` 或超出范围的比赛 ID 都会被后端拒绝。

## 千问调用与本地降级

### QWEN TOOL CALLING

配置 `DASHSCOPE_API_KEY` 后，后端先发送：

- 用户问题；
- 允许使用的球队与球员实体；
- 七个 JSON Schema 工具定义；
- 明确的数据边界和最多四次调用限制。

千问返回 `tool_calls` 后，后端不会信任参数，而是再次执行本地解析和 Pydantic 校验。工具输出完成后，第二次调用只负责生成 `headline` 和 `answer`，排名、积分、比分、xG 与球员得分均来自本地结果。

在请求千问前，本地路由还会生成一份“问题能力范围”。模型返回的工具种类、调用次数和规范化实体必须与该范围一致；即使函数本身合法，只要被用在错误问题上，也会放弃该计划并执行本地安全计划。

### LOCAL TOOL ROUTER

没有 API Key、请求超时、工具计划无效或模型选择未知工具时，系统切换到本地路由：

- 识别中英文球队、球员别名和数据任务关键词；
- 使用同一个工具执行层；
- 使用本地证据模板组织回答；
- 保留相同的工具轨迹、数据源和限制。

因此无 Key 环境仍可完整演示，不会把降级变成无依据的自由回答。

## API

### 能力状态

```http
GET /api/copilot/capabilities
```

返回千问配置状态、默认执行模式和七个工具的数据范围，不返回 API Key。

### 执行查询

```http
POST /api/copilot/query
Content-Type: application/json

{
  "question": "利物浦和阿森纳的最终排名、主客场表现和近五场状态有什么差异？",
  "season": "2024-25"
}
```

响应包括：

- `generation`：`qwen_tool_calling` 或 `local_tool_router`；
- `tool_calls`：顺序、调用 ID、函数名、规范化参数、摘要和来源；
- `evidence`：页面可直接展示的结构化事实；
- `links`：进入 Form Lab、Player Lab、Match Lab 或球队页；
- `limitations` 与 `scope_notice`：数据和解释边界；
- `suggestions`：仍可由当前工具回答的后续问题。

## 实体解析

- 球队支持数据库全称、简称、slug 和常见中文别名；
- 球员支持快照中的全名、姓氏、slug 和常见中文别名；
- 解析结果必须唯一；同一姓名有多段俱乐部记录时必须提供俱乐部上下文，否则工具返回 422；
- 工具轨迹展示规范化后的 slug，便于复现同一查询。

## 数据隔离

- 积分榜和球队状态只使用 2024-25 历史快照；
- 阵容工具使用同赛季球员—俱乐部分段，位置分钟不代表阵型或实时名单；
- 球员比较只使用 2024-25 快照中达到 450 分钟的 400 条记录；完整浏览快照含 574 条记录和 562 个姓名；
- 相似球员工具使用同一快照的七项同位置百分位与位置权重，门将指标不足时只返回边界说明；
- `3749448` 射门工具只使用 2003-04 单场事件；
- 历史比赛问题命中后不会额外调用 2024-25 球队状态工具；
- Copilot 不查询实时新闻、伤病、转会、赛程或比分。

## 当前边界

- Copilot 查询暂不写入 `agent_runs`；Agent Notebook 仍只保存双球员分析与追问链。
- 不支持任意 SQL、网页搜索、代码执行或用户自定义函数。
- 不自动延续上一条 Copilot 问题；每次请求都独立规划。
- 球队状态只由最终比分计算，不能推断阵型、控球、伤病或比赛过程。

## 测试覆盖

`backend/tests/test_copilot_api.py` 覆盖：

- 七工具能力注册表；
- 单队阵容结构的本地路由、分钟门槛与证据边界；
- 本地积分榜路由；
- 两队八维对阵的单工具组合；
- 球员别名与创造侧重点；
- 相似球员本地路由、规范化参数与门将数据边界；
- 历史比赛赛季隔离；
- 越界问题 422；
- 模拟千问先返回 `tool_calls`、再基于后端证据生成 JSON 回答。
- 千问选择“合法但与问题无关”的工具时自动回退本地安全计划。
